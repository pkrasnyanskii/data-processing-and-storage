# C6 — бронирование авиабилетов на STM

Карта рейсов: у каждого рейса цена и `ref` с числом билетов (валидатор не даёт уйти в минус).
`book-tickets` ищет самый дешёвый маршрут алгоритмом Дейкстры по рейсам, на которые ещё остались
билеты (больше пересадок допустимо, если так дешевле), и уменьшает билеты на всех рейсах маршрута в
одной транзакции `dosync`. Либо забронированы все перелёты, либо ни одного: если маршрута нет,
возвращается `{:error :no-tickets}`.

Сам Дейкстра — чистая функция (`cheapest-path`), ничего не меняет. Побочные эффекты только в
транзакции: `alter` билетов и атом `transact-cnt`, который считает запуски тела транзакции и не
откатывается вместе с ней.

## Что изменено в заготовке

- Карта `spec1` стала функцией `make-spec1`. Билеты тратятся, и повторный `run` на старой карте
  не нашёл бы ни одного. Теперь каждый запуск начинается с полными билетами.
- В `run` подобраны таймауты и выводится число перезапусков.

## Команды

```bash
lein run
```

Тесты:

```bash
lein test
```

## Таймауты

Покупатели: `City1→City3`, `City1→City2`, `City2→City3`. Дешёвые рейсы по цепочке
`City1→Town1_X→TownX_2→City2→Town2_3→City3` общие у всех троих, билетов там по 2–3.

Исходные таймауты (первый покупатель сразу, остальные через 100 мс, шаг 1 мс) не годятся: за 100 мс
первый покупатель успевает забрать всё, что нужно третьему. В 100 прогонах из 100 покупатель
`City2→City3` оставался без билетов.

Подобрано: все три начинают одновременно (задержка 0), шаг между попытками 10 мс. Тогда все
покупают в одном «раунде», и каждый получает хотя бы один билет. Проверка на 200 прогонах:

| шаг между попытками, мс | среднее число перезапусков | прогонов, где кто-то остался без билетов |
|---|---|---|
| 0 | 0.15 | 12 из 200 |
| 1 | 0.68 | 1 из 200 |
| 5 | 0.93 | 0 из 200 |
| 10 | 1.32 | 0 из 200 |
| 20 | 1.84 | 0 из 200 |

Транзакции короткие, поэтому перезапусков мало (около 13 вызовов `book-tickets` за прогон). С
ростом шага перезапусков чуть больше: покупатели выравниваются по времени и чаще сталкиваются на
одних и тех же рейсах.

Типичный результат `lein run`: 2 + 5 + 3 брони, ~15 стартов транзакций при 13 вызовах, то есть 2
перезапуска.
