# C5 — обедающие философы на STM

Философы сидят по кругу, вилка `i` лежит между философом `i` и философом `i + 1`. Каждая вилка —
`ref` со счётчиком использований. Обед — одна транзакция (`dosync`): берём обе вилки (`alter`
счётчиков) и ждём `dine-ms` внутри транзакции. Пока она не закоммичена, вилки заняты ею, и сосед,
который лезет в ту же вилку, перезапускается.

Перезапуски считает атом `attempts`: он увеличивается при каждом запуске тела транзакции и не
откатывается вместе с ней. `перезапусков = attempts − число удавшихся обедов`.

Настраивается всё из условия: число философов, время размышлений, длительность обеда, число обедов.

## Команды

Серия опытов (чётное и нечётное число философов, максимальная конкуренция, пауза между вилками):

```bash
lein run
```

Один запуск: философы, думает (мс), обедает (мс), число обедов, [пауза между вилками (мс)]:

```bash
lein run 5 10 50 20
lein run 5 0 5 200 5
```

Тесты:

```bash
lein test
```

## Формулы

`n` — число философов, `m` — число обедов у каждого, `t` — время размышлений, `d` — длительность
обеда (вместе с паузой между вилками).

За столом одновременно едят не больше `⌊n/2⌋` философов, поэтому

`T ≥ max( m · (t + d),  n · m · d / ⌊n/2⌋ )`

При чётном `n` второй член равен `2 · m · d` и от `n` не зависит. При нечётном `n` он равен
`2n/(n − 1) · m · d`: хуже всего у трёх философов (`3 · m · d`), с ростом `n` приближается к чётному
случаю.

## Результаты

`t = 10 мс`, `d = 50 мс`, `m = 20` (замер на машине с 2 ядрами):

| n | время, мс | оценка снизу, мс | запусков транзакций | перезапусков |
|---|---|---|---|---|
| 2 | 2054 | 2000 | 79 | 39 |
| 3 | 3071 | 3000 | 184 | 124 |
| 4 | 2086 | 2000 | 162 | 82 |
| 5 | 2543 | 2500 | 248 | 148 |
| 6 | 2033 | 2000 | 258 | 138 |
| 7 | 2445 | 2333 | 357 | 217 |
| 8 | 2750 | 2000 | 451 | 291 |

Время почти совпадает с оценкой: три философа действительно обедают заметно дольше, чем четыре
(нечётное число хуже), а перезапусков становится больше с ростом `n`.

## Livelock

Нужен бесконечный цикл перезапусков, где никто не обедает. Пробовал самые неприятные настройки:
без размышлений (`t = 0`), длинный обед, пауза между взятием левой и правой вилки (все держат
левую и ждут правую). Например, `n = 5`, `t = 0`, `d = 1`, пауза 1 мс, `m = 300`: 5538 запусков
транзакций, из них 4038 перезапусков, то есть три из четырёх попыток впустую.

Но завершались все прогоны, а счётчики вилок получались ровно `2 · m`. Полноценный livelock в STM
Clojure не получился: при конфликте побеждает самая старая транзакция (её время старта сохраняется
при перезапуске, и через ~10 мс она может «оттеснить» более молодую), поэтому кто-то всегда
продвигается. Конкуренция проявляется как лавина перезапусков и потерянное время, но не как вечный
цикл.
