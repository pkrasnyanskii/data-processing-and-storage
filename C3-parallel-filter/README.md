# C3 — параллельный filter

`pfilter` режет последовательность на блоки по `block-size` элементов, каждый блок фильтруется в
своём `future`. Результат ленивый, порядок как у обычного `filter`, вход может быть бесконечным.

Как сохраняется ленивость: заранее запускается не больше `число ядер + 2` блоков (так же сделан
`pmap`), поэтому на бесконечной последовательности считается только то, что нужно потребителю, плюс
небольшой запас.

```clojure
(pfilter pred coll)               ; блок по умолчанию 1000
(pfilter pred coll block-size)
```

## Команды

Замеры через `time`:

```bash
lein run
```

Тесты:

```bash
lein test
```

## Результаты

Предикат — пробное деление (`heavy?`), 300 000 чисел начиная с 10⁹, найдено 14 491 простых.
Замер сделан на машине с 2 ядрами; на своём компьютере результаты будут другими.

| вариант | время, мс |
|---|---|
| `filter` | 4987 |
| `pfilter`, блок 100 | 2998 |
| `pfilter`, блок 1000 | 2326 |
| `pfilter`, блок 10000 | 2227 |

Ускорение примерно в 2 раза при 2 ядрах. Совсем мелкие блоки (100) заметно хуже: на каждый блок
приходится отдельный future, и накладные расходы заметнее.

Первые 2000 простых из бесконечной последовательности: `filter` — 572 мс, `pfilter` (блок 500) —
351 мс.
